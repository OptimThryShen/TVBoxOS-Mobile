# 下载文件：存储权限、TS 时间轴和 MP4 转封装

## 问题及处理

### 自建目录提示权限不足

下载默认写在 App 自有目录，该目录可写并不代表 `/storage/emulated/0/test2026` 等公共自建目录也可写。

下载管理中的单文件及批量“移动到”现在都会先检查并申请文件访问权限。Android 11+ 需要在系统页面允许“所有文件访问权限”；拒绝授权不会移动或删除文件。授权后再打开目录选择器，仍以实际读写结果判断是否成功。此授权不能绕过 Android 对其他 App 的 `Android/data` 私有目录的限制。

同目录移动不生成额外副本；同卷改名先于复制空间检查，避免不需要复制时仍报空间不足。

### TS 只能控制前约 12 秒

HLS 分片按字节直接拼接时，分片时间戳可能反复从零开始。只更换播放器或扩大首尾探测范围，仍会把“完整视频”误认为一个分片的长度。

`TsTimestampNormalizer` 对有限的、188 字节包格式 TS 顺序扫描：

- 检测较大的 PCR / DTS 回退，展开为连续时间轴，并同步平移 PCR、OPCR、PTS 和 DTS。
- 保留 PTS 与 DTS 的差值，避免把正常 B 帧显示顺序误判为分片重置；处理 33 位时间戳自然回绕。
- 重建 TS 连续计数器，处理跨数据包的 PES 时间戳头。
- 新下载在合并结束后处理；已有 TS 在本地播放前后台检查，必要时使用修复缓存，不覆盖原文件，不需要重新下载。
- 缓存按原路径、长度和修改时间区分。首次检查大文件可能需要等待，并需要约一份文件大小的临时空间。
- 本地 TS 使用 Exo；切集先释放旧引擎，再按当前文件建立播放器，防止实际仍沿用上一集引擎。

这不是视频转码。损坏、加密、非 188 字节 TS、PID/编码配置更换、缺失关键时钟等情况仍可能无法修复，会保留原文件并提示失败。

### 转 MP4 的 writeSampleData 错误

部分系统的 TS MediaExtractor 返回带 ADTS 头、甚至一包包含多帧的 AAC 数据。MP4 需要逐帧写入不带 ADTS 头的 AAC，不能原样交给 MediaMuxer。

- 先修复 TS 时间轴，再去掉 AAC ADTS 头、拆成独立帧并计算各帧时间。
- 独立编码分片边界上小范围重叠的音频帧不重复写入；大范围音频时间戳异常则停止转换并保留 TS。
- 显式映射 MediaExtractor / MediaCodec 标志，不把两套标志直接混用。
- 使用临时 MP4 和不覆盖同名文件的输出路径（兼容 `.TS`）；完成收尾后重新读取并核对每条轨道的采样数，成功后才更新结果和删除原 TS。
- 失败删除不完整输出，保留原 TS；不再使用“输出必须大于原文件 80%”这一不可靠的内容完整性判断。

运行时修改的下载类原本由工作流补丁生成，因此本次改动放在可审阅的 `.github/patches/stage6.patch`，按顺序在 stage3/4/5 之后应用。新的通用工具和单元测试是正常源码文件。

## 自动检查

Android SDK 33 + JDK 11 环境，先按工作流应用下载补丁，再运行：

```sh
./gradlew :app:testDebugUnitTest assembleRelease
```

单元测试覆盖连续时钟、3 个重置时间戳的 12 秒分片、33 位回绕、B 帧、跨包 PES、原文件保护、缓存及 ADTS 拆帧。播放器选择测试继续保留。

真实音视频回归（需 `ffmpeg`、`ffprobe`、JDK、Python 3；不需要 Android 设备）：

```sh
bash tests/verify-ts-timeline.sh
```

脚本生成 H.264（含 B 帧）+ AAC 的 12 秒 TS，重复拼接三次以复现“时长只有 12 秒”，确认修复后为约 36 秒、900 帧，且定位至 24 秒能解码。该检查不等同于 Android 真机上的 MediaMuxer 和文件权限测试。

## 真机回归

1. 不授予文件管理权限，在下载管理选择单文件及批量“移动到”，确认出现授权说明及系统授权页。拒绝时原文件及任务路径不变。
2. 授权后移动 MP4 至 `/storage/emulated/0/test2026`，确认文件可播放、任务路径已更新、旧文件已移除；再选择相同目录，不应生成 `(1)` 副本。
3. 对已有的问题 TS 打开播放，等待首次时间轴检查，检查总时长及 25% / 75% 前后拖动，特别检查超过 12 秒的位置。退出重开确认恢复进度。
4. 将同一 TS 手动转换 MP4，确认进度、画面、音频同步正常，无 writeSampleData 错误；失败必须保留原 TS。
5. 目标目录已有同名 MP4 时转换，确认不会覆盖现有文件；测试大写 `.TS`、空格、中文、`#` 文件名。
6. 新下载分别开启/关闭自动转 MP4，检查输出完整；混合列表 TS → MP4 → TS 切集时播放器配置正确。
7. 在 TS 后台准备期间快速切集或退出，确认旧请求不会启动播放；检查在线 MP4 / HLS 点播和直播不受本地文件修复影响。
