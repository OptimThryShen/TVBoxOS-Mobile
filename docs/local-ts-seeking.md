# 本地 TS 拖动进度回归检查

## 修改范围

- 本地播放 `.ts` / `.TS` 文件时使用 Exo；逐集复制播放器配置，不修改全局偏好。
- 普通文件的 ProgressiveMediaSource 接入项目已有的 TS 时间戳搜索配置，显式使用 SINGLE_PMT 模式。
- HLS 仍使用 HlsMediaSource，不将直播分片当作可定位文件处理。
- 本地文件 URI 用 Uri.fromFile 创建，避免文件名中的 `#` 等字符截断路径。

TS 不像 MP4 那样自带完整索引。Exo 需要有限文件长度、有效的 PAT/PMT 和首尾 PCR 时间戳来计算时长及建立二分搜索定位。此修改不保证修复损坏、缺失 PCR、加密或有时间戳跳变的拼接文件。

## 自动检查

在配置了 Android SDK 33 及兼容项目 Gradle 7.3.3 的 JDK（例如 JDK 11）的环境运行：

```sh
./gradlew :app:testDebugUnitTest
```

`PlayerHelperTest` 覆盖 TS 播放器选择、大小写、原配置隔离、混合格式切集及其他播放参数保留。它不验证设备上的解码和实际 seek。

## 真机检查

1. 将一个已完整下载、已知可定位的 TS 视频放到手机，分别把全局播放器设为系统、IJK 和 Exo，从本地视频列表打开。
2. 确认显示正确总时长，向前/向后拖到约 25%、75% 后松手，确认播放位置和声音均移动，而不是从头重播。
3. 使用屏幕滑动手势快进/快退；暂停后拖动，再继续播放。
4. 退出后重新打开，确认恢复上次进度。
5. 在同一列表中按 TS → MP4/MKV → TS 切集，确认普通格式仍使用原播放器，TS 使用 Exo；全局设置未改变。
6. 用大写 `.TS`，以及含空格、中文、`#` 的文件名重复检查。
7. 检查在线 MP4、HLS 点播及 HLS 直播，确认原播放路径未被 TS 文件处理逻辑替换。
8. 对原先出问题的视频重复上述步骤。若仍无总时长，应检查容器是否包含有效且连续的 PCR 时间戳，而非强行按文件字节百分比伪造时间进度。
